# Мечты добрых сердец — благотворительный лендинг

Лендинг + админ-панель для благотворительного фонда «Мечты добрых сердец».
Фронтенд и админка лежат в одном приложении, бэкенд — отдельный API на
Express + PostgreSQL.

## Стек

| Слой       | Технология |
| ---------- | ---------- |
| Фронтенд   | React 19 + Vite + TypeScript + Tailwind v4 + shadcn/ui + framer-motion + wouter |
| API        | Node.js 20+, Express 5, TypeScript |
| БД         | PostgreSQL 14+ (Drizzle ORM, drizzle-kit) |
| Контракт API | OpenAPI 3.1 + Orval (автогенерация хуков) |
| Управление | pnpm workspaces (монорепо) |
| Веб-сервер | Nginx 1.18+ (reverse proxy + статика) |
| Прод-процесс | pm2 |

> На площадке Replit pnpm и автоматический деплой настроены платформой —
> ничего вручную ставить не нужно. Раздел «Деплой на свой сервер» нужен
> только если вы поднимаете проект на собственной Ubuntu 22.04.

## Переменные окружения

Скопируйте `.env.example` в `.env` и заполните значения. Значения объяснены
в самом примере. Минимальный набор:

| Переменная        | Назначение |
| ----------------- | ---------- |
| `DATABASE_URL`    | Строка подключения к PostgreSQL |
| `SESSION_SECRET`  | Секрет для подписи сессионных cookie |
| `ADMIN_USERNAME`  | Логин администратора (создаётся при первом старте) |
| `ADMIN_PASSWORD`  | Пароль администратора (создаётся при первом старте) |
| `PORT`            | Единый порт приложения (API + фронтенд) |
| `BASE_PATH`       | Базовый путь фронта (для прод-деплоя `/`) |
| `NODE_ENV`        | `production` для прод-сборки |
| `PUBLIC_EMAIL`    | Публичный email фонда по умолчанию |
| `ADMIN_NOTIFICATION_EMAIL` | Email для заявок по умолчанию |
| `SMTP_HOST` / `SMTP_PORT` / `SMTP_USER` / `SMTP_PASS` / `SMTP_FROM` | SMTP-настройки для отправки писем |

## Админ-панель

Доступ: открыть `https://<домен>/admin/login`.

Логин/пароль по умолчанию: `admin` / `admin12345`. После первого входа
зайдите в раздел БД (или просто перезайдите с новыми значениями
`ADMIN_USERNAME` / `ADMIN_PASSWORD` в `.env`) и измените их.

В админке есть вкладки:

- **Подопечные** — добавление/редактирование/удаление карточек детей,
  обновление сумм сбора, фото, истории, переключатель «срочный сбор».
- **Истории** — карусель «истории спасённых».
- **Отчёты** — загрузка PDF (вставкой ссылки на файл; недельные отчёты
  показываются на сайте, через 7 дней автоматически уходят в архив).
- **Заявки** — просмотр всех форм: волонтёры, материальная помощь,
  заявки на размещение ребёнка, сообщения с формы «Связаться».
- **Статистика** — недельная статистика кликов «Пожертвовать».
- **Настройки** — название фонда, слоган, миссия, юридический адрес,
  email/телефон, ссылка на пожертвования, реквизиты, QR-код, логотип
  и его размер, ссылки на соцсети, документы фонда.

## Локальный запуск (разработка)

```bash
pnpm install
pnpm --filter @workspace/db run push   # применить схему БД
pnpm --filter @workspace/api-spec run codegen  # обновить хуки/zod, если меняли openapi.yaml
PORT=80 pnpm run dev
```

Если порт `80` занят или система не даёт открыть привилегированный порт без
дополнительных прав, используйте, например, `PORT=8080 pnpm run dev`.

Откройте `http://localhost` при `PORT=80` или `http://localhost:8080` при
другом значении `PORT`. И API, и фронтенд теперь обслуживаются через один
порт одним сервером.

## Рекомендуемые характеристики сервера

Проект теперь хранит не только данные сайта, но и локально загруженные
файлы: логотип, документы фонда, фотографии подопечных, галерею и баннеры.
Поэтому требования к диску и памяти выше, чем у обычного лендинга.

### Минимум для тестового или малого запуска

- `2 vCPU`
- `4 GB RAM`
- `35 GB SSD`
- `Ubuntu 22.04 LTS`
- `Node.js 20+`
- `PostgreSQL 14+`
- `Nginx 1.18+`

### Рекомендуемо для боевого запуска

- `4 vCPU`
- `8 GB RAM`
- `80 GB SSD`
- отдельный swap `2-4 GB`
- ежедневные бэкапы базы и папки с загрузками

### Если ожидается активная загрузка фото и документов

- `4-6 vCPU`
- `8-16 GB RAM`
- `120+ GB SSD`
- желательно вынести PostgreSQL на отдельный managed-инстанс или второй сервер
- желательно подключить внешнее файловое хранилище или резервное копирование папки загрузок

### Что влияет на размер сервера

- количество фотографий в карточках подопечных и в галерее мероприятий
- количество PDF-отчётов и документов фонда
- число одновременно открытых админских сессий
- объём логов и глубина хранения резервных копий

## Деплой на свой сервер (Ubuntu 22.04 + Nginx) — пошагово

1. **Подключитесь по SSH к серверу:**
   ```bash
   ssh root@<IP-сервера>
   ```
2. **Клонируйте репозиторий:**
   ```bash
   git clone <ваш-git-url> /opt/mds && cd /opt/mds
   ```
3. **Запустите автоматический установщик (поставит Node, PostgreSQL,
   Nginx, certbot, pm2 и применит конфиг nginx):**
   ```bash
   sudo bash deploy/install.sh
   ```
   Скрипт спросит домен и email для Let's Encrypt.
4. **Создайте `.env`** в корне проекта по образцу `.env.example`
   (значения для подключения к БД и пароля админа подскажет инсталлятор).
5. **Соберите и задеплойте проект (первый запуск):**
   ```bash
   bash deploy/release.sh
   ```
6. Проверьте сайт по домену. Админка — `/admin/login`.

### Что делает каждая команда

| Команда                                  | Что делает |
| ---------------------------------------- | ---------- |
| `apt-get install -y nginx postgresql`    | Ставит nginx и Postgres |
| `npm install -g pnpm pm2`                | Ставит менеджер пакетов и менеджер процессов |
| `pnpm install --frozen-lockfile`         | Ставит зависимости проекта без изменений lock-файла |
| `pnpm run build`                         | Собирает API (esbuild) и фронт (vite) |
| `pnpm --filter @workspace/db run push`   | Применяет схему БД (drizzle-kit push) |
| `rsync -a artifacts/site/dist/public/ /var/www/mds-site/` | Копирует собранную статику фронта |
| `pm2 start ... --name mds-api`           | Запускает API как фоновый процесс с автоперезапуском |
| `pm2 save && pm2 startup`                | Сохраняет список процессов и включает автозапуск при ребуте |
| `nginx -t && systemctl reload nginx`     | Проверяет и перечитывает конфиг nginx |
| `certbot --nginx -d ...`                 | Выпускает HTTPS-сертификат и правит конфиг nginx |

## Деплой обновления проекта

После того как вы что-то поменяли в репозитории и запушили в git:

```bash
ssh root@<IP-сервера>
cd /opt/mds
git pull
bash deploy/release.sh
```

`release.sh` автоматически: ставит новые зависимости, собирает проект,
применяет миграции БД, обновляет статику фронта и перезапускает API.

## Robots.txt и Sitemap.xml

Файлы лежат в `artifacts/site/public/`:

- `artifacts/site/public/robots.txt` — закрывает админку от индексации.
- `artifacts/site/public/sitemap.xml` — карта сайта с якорями.

При сборке Vite копирует их в корень `dist/public/`, и они становятся
доступны по `/robots.txt` и `/sitemap.xml`. Если меняете домен — поправьте
адрес `Sitemap:` в `robots.txt`.
